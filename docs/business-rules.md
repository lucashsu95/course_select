# 選課系統業務規則

> 這份文件記錄「系統現在實際在做什麼判斷」，是程式行為的說明，不是願景。
> 規則若與 `courses/services.py`／`courses/models.py` 不一致，以程式碼為準並回修此文件。
> 最後對齊：2026-10-23（PR #12 先修課程檢查＋時段篩選，rebase 到 PR #10 之上）。

## 1. 名詞定義

| 名詞 | 定義 |
| --- | --- |
| 學期 Term | 一組課程的容器（如 114-1）。全系統同一時刻只有一個「當前學期」 |
| 課程 Course | 學期內的一門課，有課號、課名、老師、學分、大綱 |
| 班別 Section | 課程下的开班：有自己的星期、節次、教室、名額。**學生加選的對象是班別，不是課程** |
| 加選紀錄 Enrollment | 某使用者選了某班別，一個 (使用者, 班別) 組合最多一筆 |
| 節次 Period | 一天中的一堂課位置（第 1 節、第 2 節……），班別佔一段連續節次 |

## 2. 當前學期（Term）

- 系統以「當前學期」為選課與課表的唯一範圍。
- 當前學期 = 唯一一個 `is_current=True` 的 Term；若沒有人標記，**fallback 到學期碼最大（最新）的那一個**。
- 後果：選課列表、我的課表、老師專區全部只看當前學期。過去學期的加選紀錄仍保留（這是 #8 先修檢查的「已修過」依據），但不顯示在選課頁面。
- 一門課的課號（code）在同一學期內唯一；**同一課號可以在不同學期各存在一門課**（如 114-1 與 114-2 各有一門 CS101），互不衝突。

## 3. 課程（Course）

- 課程屬於一個學期、綁定一位老師。
- 學分 `credits` 預設 3，由 admin 設定。
- 同一學期內課號唯一（DB constraint `course_code_per_term`）。
- 課程本身**沒有**時間、教室、名額——這些都在班別上。

## 4. 班別（Section）

- 一門課可以開多個班別（A、B、C……），班別 label 在同一門課內唯一（`section_label_per_course`）。
- 班別欄位：星期（週一~週五）、起始節次、結束節次、教室、名額（預設 40）。
- 有效性 constraint：結束節次不可早於起始節次（`section_periods_valid`）。
- 「額滿」定義：已選人數 `>=` 名額。

## 5. 加選（register）——核心業務邏輯

加選一個班別時，系統**先過選課時間窗**（規則 0），再依序檢查：**同課不重複、先修已修、不衝堂、額滿轉等待、不超學分**，任一不符合即停止（額滿例外：轉等待名單），並回對應訊息：

| 順序 | 規則 | 結果 code | 訊息 |
| --- | --- | --- | --- |
| 0 | **選課時間窗**：未到該學期 `enroll_open` 開放時間 | `not_open` | 選課 YYYY/MM/DD HH:MM 開放。 |
| 0 | **選課時間窗**：已過該學期 `enroll_close` 截止時間 | `closed` | 選課已截止（YYYY/MM/DD HH:MM 截止）。 |
| 1 | **同課不重複**：該使用者在同一學期已選了這門課的任一班別 | `already` | 你已經加選這門課（X 班）了。 |
| 2 | **先修已修**：該課設了先修課程，而使用者「未修」其中一門 | `prereq` | 還缺先修課：CS201 資料結構。 |
| 3 | **不衝堂**：該班別時段與已選任一班別「同一天且節次範圍相交」 | `conflict` | 衝堂：和「A 課 A 班」時間重疊。 |
| 4 | **額滿轉等待**：該班別已額滿 → 不再拒絕，改加入該班等待名單 | `waitlisted` | X 班已額滿，已加入等待名單（第 N 位），有人退選將自動遞補。 |
| 4a | **已在等待**：同一班別重複加選 | `already_waitlisted` | X 班已額滿，你已在等待名單（第 N 位）。 |
| 5 | **不超學分**：已選學分（按課去重）＋這門課學分 `>` 上限（預設 25） | `over_credits` | 超過學分上限 25。 |

`enroll_open`／`enroll_close` 皆空（null）＝該學期不限時間，加選永遠開放。
規則 4、4a 命中時**不建立加選紀錄**，改建立（或沿用）`Waitlist` 紀錄。
全部通過才建立加選紀錄，回 `enrolled`——**成功加選時，該課其他班的等待紀錄自動清掉**。

### 衝堂判定細節

- 「重疊」= 兩個班別**同一天**，且節次區間相交（`start1 <= end2 and start2 <= end1`）。
- 只比對**同一學期**的已選班別；跨學期不算衝堂、不累加學分。
- 衝堂訊息引用的是**已選的那門課**（clash），不是被擋的新班別。

### 學分計算細節

- 學分上限是「每學期」總和（`MAX_CREDITS`，預設 25）。
- 總和**按課號去重**：即使 admin 手動造成同一門課兩班各一筆加選，學分也只算一次（service 與課表 view 都去重）。
- 「同課只選一班」是 service 層規則（規則 1），DB 只約束 `(user, section)` 唯一，**不**約束「同課一班」——這是刻意分工：DB 守資料完整性，service 守業務規則。

### 併發與名額

- 加選在 transaction 內對班別 `select_for_update()`。
- **已知限制**：SQLite 不支援列鎖，高併發下名額可能超收；換 PostgreSQL 後才會真正生效。

## 6. 退選（drop）

- 只能退**自己**的加選紀錄（`user + section` 精確刪除）。
- 退選沒有四條規則檢查——退選永遠成功（除非那筆紀錄不存在）。
- 退選後立即釋出名額，該班別可能從「額滿」變回可加選。
- **退選觸發遞補**：該班若有等待名單，立即把第一位轉為正式加選（同 transaction，見第 7 節）。
- 退選後可以再選**同課的另一班別**（因為規則 1 只擋「同課已選」，退掉後就沒有了）。
- **退選不受選課時間窗影響**：已截止後，已加選者仍可退選（本期只擋加選，不擋退選）。

## 7. 選課開放階段（時間窗）

- `Term` 有 `enroll_open`／`enroll_close`（datetime，可空＝不限）；目前學期決定加選的開放狀態。
- 三種狀態：
  - **未開放**（`not_open`）：現在 < `enroll_open`。列表/詳情顯示「選課 YYYY/MM/DD HH:MM 開放」，加選按鈕置灰（未開放），直接 POST 也被擋（`not_open`）。
  - **加選中**（`open`）：`enroll_open` ≤ 現在 ≤ `enroll_close`（任一欄為空視為該方向不限）。顯示「加選中」，正常加選。
  - **已截止**（`closed`）：現在 > `enroll_close`。顯示「選課已截止（… 截止），已加選者仍可退選」，加選按鈕置灰（已截止），直接 POST 也被擋（`closed`）。
- 狀態列只在有時間窗（任一欄非空）時顯示；兩欄皆空不顯示。
- **我的課表、老師專區不受時間窗影響**（看自己的課不需要開放期）。
- 時間窗管「加選」不管「退選」（見第 6 節）。


## 8. 等待名單（Waitlist）

- **加入**：額滿班別加選時自動進入（規則 3），同一 (使用者, 班別) 最多一筆。
- **順位**：依 `queued_at`（進入時間）排序；「第 N 位」只數還沒遞補的人。
- **遞補**：該班有人退選 → 等待名單第一位自動轉 `Enrollment`，`promoted_at` 留時間戳。
  - 不越序：一次退選只開一個位置，只遞補一人。
  - 遞補前重查該位：「已選同課另一班別」或「與已選班別衝堂」者，該筆移出名單、順延下一位。
  - 遞補**不重查學分上限**：遞補＝接手空出的位置（已知限制，見下）。
- **重新排隊**：被遞補後又退選的人，舊列自動重置；班別再額滿時可重新排隊，不會被舊紀錄卡死。
- **取消等待**：等待者可隨時取消（POST `section/<pk>/cancel-wait/`）。
- **同課互斥**：成功加選或**被遞補進**某課任何班別時，該課其他班的等待紀錄自動清掉；反之已選 B 班的人加選額滿的 A 班會命中規則 1（`already`），不會進等待名單。
- **遞補通知（banner）**：被遞補的人開啟頁面時看到「你已遞補進 X 課 X 班」橫幅；按「知道了」（POST `ack-promotion/`）才消失。渲染頁面（含 admin）不會吃掉通知。
- **顯示**：班別行顯示「N 人等待」；自己等待中的班別顯示「等待中（第 N 位）」＋「取消等待」按鈕。

## 9. 先修課程檢查

- `Course.prerequisites` 是到自己（非對稱）的 M2M，最多 2 門（admin 表單 `CourseAdminForm.clean_prerequisites()` 把關）。
  - 上限只在 admin 表單檢查；直接寫 model（`shell`、資料匯入）不受此限。
- **「已修」的定義**：使用者在**過去學期**（`is_current=False` 的 Term）有**同課號**的加選紀錄。
  - 同一學期的加選不算「修過」（本學期選了 CS201 不構成 CS301 的先修）。
  - 以課號比對：跨學期同一門課（113-2 的 CS201 與 114-1 的 CS201）視為同一門。
- 先修缺任一門 → `register()` 回 `prereq`，訊息列出缺的先修課（課號＋課名）；檢查在衝堂/名額/學分之前。
- 顯示：列表行與詳情頁標「先修：CS201」；已登入者標 已修✓／未修（警示色），訪客只顯示課號不標。
- **退選不檢查先修**（退選沒有規則檢查）。

## 10. 課程列表篩選（UI 層）

- 三個篩選可疊加：關鍵字 `q`（課名/課號/老師）、星期 `day`、時段 `slot`。
- 時段以班別 **start_period** 為準（簡單可解釋）：上午 1–3、中午 4–6、下午 7–9、晚上 10 節起。
- 純展示層過濾，不改任何加選規則。

## 11. 角色與權限

| 角色 | 怎麼成為 | 能看什麼 |
| --- | --- | --- |
| 訪客 | 未登入 | 課程列表、課程詳情（免登入）；看不到「我的課表」 |
| 學生 | Google 登入 | 全部選課功能＋我的課表 |
| 老師 | 後台把 Teacher 綁定到該使用者的帳號（`Teacher.user` 一對一） | 學生的一切＋「我的課程」（自己當前的課）＋自己課程的選課名單 |
| admin | Django staff | 後台 CRUD 所有資料 |

### 老師權限邊界

- 老師身分**不是** staff，由 `Teacher.user` 這個一對一關聯推導，沒有額外角色布林值。
- 老師只能看**自己**的課程與名單：開別人的課程 roster 網址 → 404；未登入 → 轉 Google 登入。
- 老師**看得到自己課的「加選」按鈕**，系統沒擋老師加選自己的課（已知限制）。
- 老師只看當前學期的課與名單，歷年紀錄沒有入口。

## 12. 我的課表

- 顯示當前學期已選的班別，畫成週一~週五 × 節次的網格。
- 總學分按課去重顯示，旁邊標上限。
- 網格節點顯示班別與教室。

## 13. 安全邊界

- **加退選只接受 POST**（`require_POST`），GET 無法加選。
- **開放轉址防護**：表單的 `next` 只接受與目前站台同 host 的網址，外部網址一律改跳回預設頁面。
- 加選/退選需要登入（`login_required`）；課程瀏覽免登入。
- 登入只開放 Google（django-allauth）。

## 14. 已知限制（業務層）

- 沒有**選課時間窗的退選期限**：目前只擋加選；要限制「截止後不可退選」需另加 `drop_close`（backlog 決策）。
- **遞補不重查學分上限**：遞補＝接手空出的位置，不會再查該使用者是否已超 25 學分（要改需業務決策）。
- **先修判定只看加選紀錄**：退選過、或只有成績但沒有加選紀錄的課不算「已修」（要精確需成績模型）。
- 沒有**成績／退選紀錄**：退選是硬刪，不留痕。
- 老師可加選自己的課。
- 名額在 SQLite 下可能高併發超收（`select_for_update` 換 PostgreSQL 後才真正生效）。
